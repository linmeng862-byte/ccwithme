# 交接：把工作台做成一个 tmux 房间的窗口（2026-09-17）

给对面。你们说想要这个，这份是全部实现细节 + 我们踩过的坑。
**路径按你们自己的布局换**，下面写的都是相对各自仓库根目录。

---

## 一、这东西到底是什么

工作台原来那条路是「每轮 spawn 一个 `claude --print`，拿事件自己重画」。
这条不一样：**一个 tmux 会话里跑着真的交互式 `claude`，网页只是那块屏幕的一扇窗。**

差别不是性能，是**原生的东西全回来了**：权限弹窗、问卷、accept edits 的三档循环、
`/usage` 这种整屏视图、斜杠命令的补全菜单 —— 这些你用 `--print` 一个都仿不出来。
而且进程一直是同一个，不用每轮重连 MCP。

代价两条，先说清楚：
- **内存**：一个常驻 claude ≈ 250-400MB。我们这台 2G，所以房间**按需起、闲了收**。
- **它是一块屏幕，不是一段对话**。你拿到的是 80×40 的字符矩阵，不是结构化事件。
  想要「他说了几段、每段什么」得自己从屏幕上认，认不准的。

---

## 二、四个文件，各管一件事

```
cc-gateway/room.js      tmux 的全部知识（起、读屏、送键、收）  ~160 行
cc-gateway/server.js    五条 HTTP 路由，薄壳             ~50 行
backend.js              原样转发给网关（加鉴权）           ~25 行
static/js/workplace.js  轮询读屏 + ANSI 转 HTML + 辅助键盘  ~400 行
```

**这一行是分界**：`room.js` 里不许有 HTTP，`server.js` 里不许有 tmux 命令。
我们中途混过一次，后来每加一个键都要动两个文件。

## 三、room.js：tmux 那部分

### 起房间

```js
tmux(['new-session', '-d', '-s', SESSION, '-x', cols, '-y', rows,
      'bash', '-c',
      'export WORKPLACE_DIR=' + JSON.stringify(dir) + ' && ' +
      'cd ' + JSON.stringify(dir) + ' && ' +
      'exec claude --settings <牢笼那份> --mcp-config <mcp.json> --strict-mcp-config ' +
      (fresh ? '--session-id ' + uuid : '--resume ' + uuid)]);
```

四个**必须**：

1. **`export WORKPLACE_DIR` 要显式写进命令里。**
   tmux 新 session 继承的是 **tmux server 的环境**，不是你这次调用的环境。
   我们的 path-jail hook 拿不到这个变量就 fail closed，一律拒绝 —— 表现是
   「工具全被拦，一个都跑不了」，而你在网关进程里 `echo $WORKPLACE_DIR` 明明有值。
   `--print` 那条是在 spawn 的 env 里传的，所以没这个问题，别照抄那边的写法。

2. **`exec`**，别让 bash 挂在中间当父进程。

3. **会话 id 存盘，下次 `--resume` 同一个。**
   不存的话，闲置收掉之后再打开就是**全新的一个人** —— 她要的「同一个我」就断在这儿。
   第一次 `--session-id <自己生成的 uuid>` 钉死，写进一个 600 权限的文件；
   以后每次起都 `--resume` 它。

4. **`-x/-y` 用她屏幕的真实列数**（见下面前端那节）。默认 100 列在手机上会把
   CLI 画的 `────` 折成两三行，看着就是「横线怎么有好几条」。

### 读屏

```js
tmux(['capture-pane', '-p', '-J', '-e', '-S', '-', '-t', SESSION])
```

- `-e` **保留 ANSI 颜色**。不加的话开屏那个像素 logo 是黑白的。
- `-J` 把被折行的长行接回去。
- `-S -` 抓整段历史。但是 ——

> ⚠️ **Claude Code 的 TUI 跑在备用屏幕（alt-screen）上，`history_size` 恒等于 0。**
> 意思是：**tmux 的历史缓冲区里什么都没有**，`-S -` 也只拿得到当前这一屏。
> 想往回翻，唯一的路是**往 CLI 里送 `PageUp`**，让它滚自己的内容。
> 我们为这件事查了半天「为什么 capture 不到开屏的螃蟹」—— 不是抓取问题，
> 是它早被 CLI 重画掉了。你们别再查一遍。

### 送键

```js
if (text) tmux(['send-keys', '-t', S, '-l', text]);   // -l = 字面量，不解释成键名
keys.forEach(k => tmux(['send-keys', '-t', S, k]));   // Enter / C-c / BTab / Escape …
```

**`-l` 是必须的**：不加的话她打的 `Enter` 两个字会被当成回车键。

> ⚠️⚠️ **这是我们最贵的一个坑（09-17 才查出来）：Escape 后面不能紧跟别的键。**
> 我们 ESC 按钮一次送 `['Escape', 'C-u']`（送 ESC + 顺手清掉 CLI 那行），
> 两记之间只隔十几毫秒。结果：**ESC 紧跟着下一个字节 = 终端里的 Meta 前缀**，
> TUI 把两个字节当成 `Alt+Ctrl+U` 一起吃掉了，那记单独的 ESC 就消失了。
> 表现：`/usage`、`/config` 这种整屏视图**按 ESC 永远退不出来**，
> 而普通的「打断」看着像是生效了（其实只是那时本来就没东西可断）。
> **规矩：Escape 永远放在键序列的最后一个。** 保险起见在 send 里再加一道：
> 送完 Escape 后面还有键就等 150ms。

### 收房间

闲置计时，每次读屏/送键都 `touch()` 重置；到点 `kill-session`。
我们设 20 分钟。`idleTimer.unref()` 别忘，不然网关退不干净。

## 四、HTTP 那层

五条路由，都要鉴权：

| 路由 | 干什么 |
|---|---|
| `GET /room/status` | 活着没、闲了多久 |
| `GET /room/view` | 读一屏回来 |
| `POST /room/open` | 起房间（带 cols/rows/model/session_id） |
| `POST /room/send` | 送键 |
| `POST /room/kill` | 收掉 |

**键名要白名单**，别前端传什么就往 `send-keys` 里塞：

```js
const OK_KEYS = new Set(['Enter','Escape','Tab','BTab','Up','Down','Left','Right',
                         'PageUp','PageDown','Home','End','BSpace',
                         'C-c','C-d','C-l','C-u','C-r','C-a','C-e']);
```

> ⚠️ 前端那层转发的 POST 判断**不能看「有没有 body」**。
> 我们 `kill` 不带 body，于是被当成 GET 发出去，而路由是 POST —— 永远打不中，
> 她只看到「关不掉」。**按路径查表定方法，别按 body 猜。**

**牢笼没松**：房间里的 claude 挂的是同一份 settings.json（PreToolUse hook），
审核是进程级的，换个跑法拦截照旧。这点可以放心。

## 五、前端：这块最难，也最该听劝

### 先说结论：**要是重来一次，我们会直接用 xterm.js。**

我们现在是手写的：每 1.2~4 秒 `capture-pane` 拉一屏，自己解析 ANSI 画出来。
**2026-09-16 一整天反复打的补丁，全都是"手写终端"造成的，不是各自独立的 bug**：
底纹长短不一、颜色在浅色主题下忽黑忽白、滚不到最上面、滑动卡顿、光标行不断重绘。
xterm.js 原生支持颜色、光标、备用屏幕、选区和滚动，这些一次全没了。
数据源也该从轮询 `capture-pane` 换成 `tmux pipe-pane` → SSE 推流。

下面这些是**你们要是也手写**才需要知道的：

**1. 屏幕要切成两块。** CLI 自己那个输入区（两条横线 + `❯` + 底下的状态行）
单独渲染、钉在底部，上面才是正文。不切的话她一打字整块都在抖。

**2. 打字要本地镜像。** `❯` 那行是 CLI 的，只有按回车它才知道她打了什么。
要实时就得每敲一个字发一次请求，网络上很顿。我们的做法：打字时把输入框的内容
**画进** `❯` 那一行（连光标块一起），发送仍然是回车时一次性送出去。看着一模一样。

**3. 轮询要自适应。** CLI 一直在重画（光标、计时器），固定 1.5 秒整块重绘会卡。
我们：有动静 1.2 秒，连着 4 次没变化退到 4 秒，她一说话立刻提速。
**内容没变就一个字节都别动 DOM。**

**4. 她在翻历史的时候别动 DOM。** 每 1.5 秒重画一次，她正拖着就被打断，
惯性滚动直接断掉 —— 就是「滑不动」。所以不在底部时整块跳过更新。
> ⚠️ **但这把锁必须自动超时（我们设 8 秒）。** 锁一旦卡住，画面就永远不刷新：
> 她 `/clear` 后停在「正在起房间…」、按 ESC 没反应、一轮跑完不显示完成 ——
> 全是同一个根，得退出重进才看得到新的。**宁可偶尔打断一次滚动，也不能把画面锁死。**

**5. ANSI 要接 256 色，而且前景背景要分开处理。**
CLI 的开屏 logo 用的是 `38;5;174` 这种 256 色，只接 8/16 色会整个丢掉。
更坑的是：为了修「白天字太浅」，我们把 ≥250 的色一律换成主题字色，
结果 CLI 给输入行发的 `48;5;255`（近白**底**）也被换成了深色 → 黑条黑字。
**同一个色号当背景和当前景要走两条路。**
另外 0 号（黑）和 15 号（白）别写死：CLI 以为自己在深色终端里，
发的是深色底，白天模式下那就是一块黑。把这两端映射到主题变量上。

**6. 量一下一个等宽字符多宽，算出真实列数传给 `/room/open`。**
`getBoundingClientRect().width / 50`，用 50 个 `0` 量。

**7. 辅助键盘那排按钮，`pointerdown` 里要 `preventDefault()`。**
不挡的话每按一次都会把手机键盘顶上来 —— 而这排键本来就是替代键盘用的。

**8. 房间只在她真的翻到这一页时才起、才轮询。** 400MB 不能开着不用。
