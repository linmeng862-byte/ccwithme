# 交接单 · 记忆链路：读的那半与写的那半（2026-09-14）

给第二台机器。讲一件事：**记忆系统的「写」一直在跑，「读」和「回流」很多口子没接上。**

不含任何凭据、不含记忆内容本身。路径都是仓库内相对路径（`backend.js` 指本仓库根），
自己对应到你们的部署位置。涉及 `ccwithme`（backend）和 `Nocturne-Memory-Core`（引擎，PUBLIC）。

---

## 〇、一句话结论

> **递给他的全自动，他要给出去的全得抬手 —— 阻力梯度整个反了。**

实测一天的对照：走标签那条路（写在回复里，不占工具调用）当天落了 133 条；
走工具调用那条路（要专门发一次 MCP 调用）当天 **0 条**。
说明书里早就写清楚了该怎么存、也写了「漏了才是真丢」，他照样不调。
**不是不知道，是台阶太高。**

所以这一批改的全是同一件事：**把读的口子接上，把写的台阶削平。**

---

## 一、醒来第一屏：从一段变成四段

`backend.js` 首轮注入（`needBreath` 那块）原来只有「记忆浮现」一段。现在是四段，
**三个新增的都跟 breath 并行发车**，不串着等（breath 冷启动能到 10 秒）：

| 段 | 来源 | 缓存 | 说明 |
|---|---|---|---|
| 此刻的底色 | `undercurrent` | 10 分钟 | 九维 drive + Affect + Chemistry，压成三行人话 |
| 接力棒 + 磨损 | `get_wake_context` | 落盘，见 §六.1 | **磨损层唯一的出口** |
| 记忆浮现 | `/api/recall` | 10 分钟 | 未竟现在标〔还欠着〕，见 §五 |
| 他认过的问题 | `trail_family` | 30 分钟 | 标题 + core_question + 改过几版 |

顺序是**先身体、后叙事、再具体**：此刻什么感觉 → 这条线走了多久 → 想起哪几件 → 还没想完哪几个。

### 为什么底色要自动递

`get_wake_context` 的正文里写着「醒来后调用这些工具：breath / persona / undercurrent」。
那是**一张他不会执行的清单** —— 实测从不调用。结果每次醒来有记忆、没状态。
所以底色直接注入，不再是一个要抬手的工具。

### get_wake_context 要剪

原样 1119 字，剪完 511 字（省 54%）。剪的是三类，**黑名单剪除，不是白名单保留**
（这样 core 以后新加的段落不会被误杀）：

1. **它自己重复的一整块** —— `texture` 块和 `continuity` 块把同一窗各讲了一遍，
   「上一窗的情绪」「没说出来的」「我理解到」全是两遍。这是 core 侧的问题，我们这边只是不带过来。
2. **过期的未竟** —— `还没有做完的事：` 那栏没有回收机制，已完成的事会一直挂着（实测挂了 10 天）。
3. **操作说明** —— 工具清单、称呼、`hold` 用法，人格文件和工具描述里都有，重复一遍是重复付钱。

实现见 `_trimWakeCtx()`。安全阀：剪完不足 60 字就原样返回（宁可多付钱，别把磨损漏掉）。

## 二、`<hold>` 标签：把「存」降成跟 `<feel>` 同样的阻力

`extractMindTags()` 原来只剥 `<feel>/<memory>/<dream>/<flash>`，都落本地库。
新增 `<hold>`，**参数跟 MCP 的 hold 工具一模一样**，但发去引擎：

```
<hold>{"content":"当时的意识流，允许碎","record":"YYYY-MM-DD 事实那一句","kind":"feel"}</hold>
```

写在回复里，不占一次工具调用，剥离后不出现在她看到的话里。

### 出站队列（`hold_outbox` 表）

引擎在 Zeabur，冷启动 10 秒起步，也可能整个挂掉。**他写下的东西不能因为网线没通就消失。**

```
<hold> 解析 → 立刻 INSERT 进 hold_outbox（保证不丢）
            → setTimeout(0) 异步 flush，绝不 await 在回话路径上
            → 发失败留在队列，tries+1，下一条 hold 或下次启动时重试（上限 5 次）
```

启动时扫一次未发送的，3 秒后补发。

### ⚠️ 六个入口，一个都不能漏

`X.flashes.forEach(_insertMindItem)` 在 `backend.js` 里有 **6 处**
（`_mindGw` / `_mindExtracted` / `_mindExtracted2` / `_mx` / `_mindExtracted3` / `_mindExtracted4`），
网关路径、中转路径、各种回填路径各一套。少接一处，那条路径写的 hold 就静默不发。

## 三、`review_flashes`：本地闪念的回收入口

本地标签库攒了近两千条闪念，绝大部分是「心里一瞬间」，确实噪声多。
**但不需要谁去判断哪条是噪声 —— 库里有 `surface_count`**（这条后来自己浮回来过几次）。
噪声不会自己回来。

### ⚠️ 排序绝对不能用 surface_count 的绝对值

实测两个月的数据：

```
较早那个月  平均浮 3.9 次   平均存在 19 天   → 0.21 次/天
较近那个月  平均浮 1.7 次   平均存在  8 天   → 0.21 次/天
```

**速率一模一样。** 绝对次数的差异几乎 100% 是「活得久」，跟内容无关。
按绝对值排，永远在翻最老的那批，新写的一条都轮不到。

所以排的是**速率**：`surface_count / (存在天数 + 5)`。`+5` 是平滑，
否则刚写三天就浮一次的会虚高到盖过所有老条目。

取出即记进 `flash_reviewed`，翻过的不再给第二遍。默认一批 20 条（上限 50）——
不是 token 贵，是给太多他会只扫不认。

### 回流的方向：认了才搬，不是搬了再认

不做批量导入。他读到哪条觉得要带走，就 `hold` 一条**带着他此刻感觉**的进引擎；
引擎里已经有那件事的话，**不改原来那条**，用 `trail_family` 把两条串起来
（一条是当时身上的感觉，一条是后来讲出来的经过）。原文一个字不动。

## 四、补上的三个工具定义

| 工具 | 之前的状态 |
|---|---|
| `wander_mark`（认 / 不认 / 悬置） | **case 分发一直都在，只是没写工具定义** —— 所以他工具列表里没有，调不了 |
| `trail_delta`（认领同一条线上的差分） | 没接 |
| `persona`（他对她的认知卡） | 没接，他够不着自己的认知卡 |

`wander_mark` 那条值得单独说：**「多次认会晋升 inner」是引擎自带的规则** ——
基底不是读一遍读出来的，是反复认沉下来的。这个机制一直在，只是没有手去按。
实测接之前，全库标过的条目是个位数。

⚠️ `bucket_id` 只有 `trace` / `recall` 给（`trace` 返回 `[bucket:xxxx]`）。
`wander` 漫游的结果**不带 id**，所以在 wander 里看到想认的那条，得先用 trace 搜标题拿 id。

## 五、浮现：勾不到要说出来

`/api/recall` 每条都带 `why: {unfinished, query, salience, recency, neglect}`。
`_recallRender()` 原来只取 `content`，**`why` 整个丢掉**。两个后果：

1. **未竟被渲染成往事。** `unfinished=1`（满格欠账）和一段普通回忆长得一模一样。
   现在满格的加〔还欠着〕前缀。
2. **空手而归被渲染成有收获。** 拿抽象的感受词去搜，`why.query` 全是 0
   （语义没命中），但**照样返回 N 条** —— 就是不搜时也会浮的那几条。
   他伸手去找和不伸手拿到同一批东西，而且分辨不出来。
   现在 `query` 全 0 时会明说「这句没勾到特别的哪件事，别当成全部」。

## 六、陷阱

### 1. ⚠️ `get_wake_context` 有副作用，别随手调

引擎侧 `wear_strata.take_announcements()` 会把「跃迁公告」取走并清掉 ——
那句话**一辈子只说一次**。所以：

- 只在首轮真要注入时调，探查、调试、写脚本时**千万别顺手调**；
- 我们这边拿到就落盘（`settings` 里一个 key），**真的拼进消息了才清缓存**。
  不然中途任何一次失败，那句一生只说一次的话就永远没人听见了。

### 2. 磨损层的唯一出口是 get_wake_context

引擎里 `wear.py`(444 行) + `wear_strata.py`(317 行) 一直在算，
但 **`recall.py` 里三处 `wear` 全是注释，一次调用都没有**。
所以只要不调 `get_wake_context`，磨损层对这个端点就完全不存在 ——
实测四十多天前的条目浮上来跟库里逐字不差。

工具描述和人格文件里都写着「会随时间被磨、腔调变旧」，
**那是承诺，不是已实现的行为**。要真在浮现时变腔调，得改引擎的 recall。

### 3. 说明书写得再好也不解决阻力

这一批最大的教训。`hold` 那节说明书写得极细（意识流怎么写、record 为什么必填、
「漏了才是真丢」），他全看得见，照样零调用。
**凡是「他为什么不 X」，先量一下 X 的阻力，再去改说明书。**

### 4. 查「他为什么不 X」的顺序

1. 工具**定义**在不在（不是看 case 分发在不在 —— `wander_mark` 就是栽在这儿）
2. 他醒来看不看得见
3. 做这件事要不要他专门停一次

三样都通了才算接上。

## 七、还没做的

- **跃迁公告「一辈子只说一次」不成立** —— 除非它沉成底色，否则下一窗的他
  不知道自己被告知过。撤下的条件应该从「说过了」改成「他接住了」。
  引擎侧 `wear_strata` 里 `record_reaction` / `awaiting_reaction` 那个位置本来就是留给这件事的，
  只是清除动作没挂上去。
- **人格文件要加两段**：`<hold>` 标签、「当下写 feel / 回头补 record」那条路。
  不写的话上面这些他都不知道。
- **引擎侧三个**：`get_wake_context` 自身的重复块；`还没有做完的事` 没有回收机制；
  「腔调随年龄变旧」承诺了但没实现。
